# ESPACIO ERP — Database Architecture Specification

## 1. Overview

The database architecture for ESPACIO ERP is designed for strict relational integrity, auditability, normalization, historical record preservation, and transaction safety.

---

## 2. Core Entity Architecture

### 2.1 Security & System Core
- **`User`**: System accounts containing email, hashed password, full name, phone, status (`ACTIVE`, `INACTIVE`, `SUSPENDED`).
- **`Role`**: Configurable roles (`ADMIN`, `LEADERSHIP`, `SALES`, `DESIGN`, `PROJECT`, `FINANCE`, `EMPLOYEE`).
- **`Permission`**: Granular permissions (e.g., `leads:read`, `leads:write`, `finance:read`, `finance:approve`, `audit:read`).
- **`UserRole`**: Junction table mapping users to assigned roles.
- **`RolePermission`**: Junction table mapping roles to assigned permissions.
- **`AuditLog`**: Centralized audit log capturing actor, action, entity type, entity ID, old values JSON, new values JSON, IP address, user agent, timestamp.
- **`ActivityLog`**: Entity activity history (notes, calls, status changes, assignments) for Leads, Projects, Quotations, Payments, Vendors.
- **`Notification`**: System notifications for users with read/unread flags.
- **`Setting`**: Key-value system preferences (Company settings, financial defaults, module flags).

### 2.2 CRM Module Shell
- **`Lead`**: CRM leads with reference ID (`LEAD-2026-0001`), client info, status (`NEW`, `CONTACTED`, `QUALIFIED`, `PROPOSAL_SENT`, `NEGOTIATION`, `WON`, `LOST`), budget, requirements, source.
- **`Client`**: Converted clients linked to projects and payments.

### 2.3 Projects Module Shell
- **`Project`**: Interior execution projects with reference ID (`PROJ-2026-0001`), stage, budget, timeline, address, assigned team.
- **`ProjectStageHistory`**: Historical record of project stage transitions.

### 2.4 Sales Module Shell
- **`Quotation`**: Formal client quotations with reference ID (`Q-2026-001`), version, total amount, status (`DRAFT`, `SENT`, `APPROVED`, `REJECTED`).
- **`QuotationItem`**: Line items for quotations (Description, quantity, unit price, tax rate, total).

### 2.5 Finance Module Shell
- **`ClientPayment`**: Client payment transactions (`PAY-2026-0001`), milestone, payment method, amount, status, date.
- **`Expense`**: Company / Project expenses (`EXP-2026-0001`), category, vendor, amount, proof receipt link, status.
- **`PettyCashAccount`**: Petty cash advances and disbursements.

### 2.6 Procurement Shell
- **`Vendor`**: Supplier/subcontractor registry (`VEN-2026-0001`).
- **`PurchaseOrder`**: POs issued to vendors (`PO-2026-0001`).

## 3. ID Strategy & Reference Numbering

All internal database records use UUID primary keys for global uniqueness.

Business-facing entities use non-sequential, concurrency-safe reference numbers generated by `IdGeneratorService`:

| Entity | Pattern Example |
| :--- | :--- |
| **Lead** | `LEAD-2026-0001` |
| **Project** | `PROJ-2026-0001` |
| **Quotation** | `Q-2026-001` |
| **Payment** | `PAY-2026-0001` |
| **Expense** | `EXP-2026-0001` |
| **Vendor** | `VEN-2026-0001` |
| **Purchase Order** | `PO-2026-0001` |

---

## 4. Preservation of Historical Records

Financial and audit history must NEVER be destroyed. 

1. **Soft Delete**: Tables maintain `deletedAt` timestamp columns where deletion is necessary.
2. **Immutable Audit Trails**: `AuditLog` rows cannot be updated or deleted by application APIs.
3. **Transaction Safety**: Financial updates execute inside Prisma `$transaction` blocks.
